# Agave

Пакетный конвертер звука для macOS. Нативный SwiftUI, универсальный бинарник
(Apple Silicon + Intel). Распространяется напрямую (Developer ID + нотаризация,
не через Mac App Store) — LAME линкуется динамически ради LGPL-2.1, а это
право пользователя заменить библиотеку App Store технически не даёт выполнить.

Перетащил файлы или папку → выбрал формат → нажал «Конвертировать». Папка
экспорта запоминается между запусками, рядом кнопка «Открыть».

---

## Установка

**Вручную.** Скачайте `Agave.dmg` со страницы [Releases](https://github.com/white-currant/Agave/releases/latest), откройте и перетащите Agave в «Программы».

**Через терминал, одной командой** (ничего больше не нужно):

```bash
curl -fsSL -o /tmp/Agave.dmg https://github.com/white-currant/Agave/releases/latest/download/Agave.dmg \
  && hdiutil attach -nobrowse -quiet -mountpoint /tmp/Agave-dmg /tmp/Agave.dmg \
  && rm -rf /Applications/Agave.app && cp -R /tmp/Agave-dmg/Agave.app /Applications/ ; \
hdiutil detach -quiet /tmp/Agave-dmg; rm -f /tmp/Agave.dmg
```

Запуск: `open -a Agave`. Удаление: `rm -rf /Applications/Agave.app`.

**Через витрину [Currant](https://github.com/white-currant/Currant)** — каталог приложений white-currant: скачивание и обновление в один клик.

Обновления приходят автоматически ([Sparkle](https://sparkle-project.org)); вручную — меню «Проверить обновления…».

Сборка из исходников описана ниже, в разделе «Сборка».

## Форматы

| Формат | Чтение | Запись | Чем реализовано |
|---|---|---|---|
| MP3 | ✅ | ✅ | LAME 3.100 |
| AAC (m4a) | ✅ | ✅ | AudioToolbox |
| Ogg Vorbis | ✅ | ✅ | libogg 1.3.5 + libvorbis 1.3.7 |
| ALAC (m4a) | ✅ | ✅ | AudioToolbox |
| FLAC | ✅ | ✅ | AudioToolbox |
| WAV | ✅ | ✅ | AudioToolbox (16 / 24 / 32-бит float) |
| AIFF | ✅ | ✅ | AudioToolbox (16 / 24 бита) |
| CAF, AC-3, MP2, AMR, звук из видео | ✅ | — | AudioToolbox |

Почему сторонние библиотеки для MP3 и Vorbis: Apple поставляет **декодер** MP3,
но никогда не поставляла кодировщик (изначально из-за патентных отчислений
Fraunhofer). Ogg Vorbis система не знает вовсе — ни на чтение, ни на запись.

Чего нет: Opus, WMA, многоканальный AC-3 на выходе. Это осознанный отказ —
догонять ffmpeg по списку форматов означало бы потерять и вес, и лицензионную
чистоту, ради которых всё затевалось.

## Настройки

- **Битрейт** для форматов с потерями: постоянный 96…320 кбит/с; для MP3 и OGG
  дополнительно переменный (V0 / V2 / V4).
- **Разрядность** для форматов без потерь: 16 / 24 бита, у WAV ещё 32-бит float.
- **Частота** и **каналы**: как в источнике либо принудительно.
  MP3 и AAC выше 48 кГц не кодируются — частота срезается автоматически.
- **Конфликт имён**: добавить номер, перезаписать или пропустить.
- **Теги** переносятся в MP3, OGG, AAC и ALAC. У FLAC не переносятся: системная
  реализация при дописывании тегов ломает STREAMINFO и портит длительность.

## Как устроено

```
Agave/
├── Model/
│   ├── OutputFormat.swift    форматы, битрейты, разрядность, настройки
│   ├── ConversionItem.swift  элемент очереди и его состояние
│   ├── ExportFolder.swift    папка экспорта + закладка с областью безопасности
│   └── AppModel.swift        очередь, запуск, отмена, сохранение настроек
├── Engine/
│   ├── AudioProbe.swift      быстрое чтение заголовка и тегов
│   ├── PCMReader.swift       чтение через ExtAudioFile + ресемплинг и сведение
│   ├── AppleAudioWriter.swift запись WAV / AIFF / FLAC / AAC / ALAC
│   ├── MP3Writer.swift       запись MP3 через LAME + теги ID3
│   ├── VorbisWriter.swift    запись Ogg Vorbis + комментарии Vorbis
│   ├── VorbisDecoder.swift   чтение Ogg Vorbis (система его не открывает)
│   ├── MP4TagWriter.swift    теги в m4a ремуксом без перекодирования
│   ├── Transcoder.swift      конвейер одного файла
│   └── ConversionRunner.swift параллельная очередь
└── UI/                       ContentView, FileRow, BottomBar, SettingsPopover
```

Ключевые решения:

- **Один конвейер на все форматы.** `PCMReader` отдаёт чередующийся Float32 уже
  в целевой частоте и числе каналов — ресемплингом и сведением занимается
  CoreAudio. Кодировщикам остаётся только принять готовые кадры.
- **Ogg на входе** разворачивается во временный CAF, дальше работает общий
  конвейер. Так не пришлось писать свой ресемплер.
- **Кодирование уходит на отдельную диспетч-очередь**, а не на кооперативный
  пул Swift: это блокирующий вызов C-библиотек, и несколько длинных файлов
  забили бы пул целиком.
- **Параллельно обрабатывается столько файлов, сколько ядер** у процессора.
- **Запись идёт во временный файл** и переносится на место только после успеха —
  оборванная конвертация не оставляет битых файлов в папке экспорта.

## Сборка

```bash
xcodebuild -scheme Agave -configuration Release
```

Библиотеки в `Vendor/` собраны заранее и лежат в репозитории. Пересобрать:

```bash
Scripts/build-lame.sh
Scripts/build-vorbis.sh
```

Скрипты качают официальные архивы (у LAME сверяется контрольная сумма), собирают
под обе архитектуры, склеивают через `lipo` и упаковывают в динамические
фреймворки. Иконка — `Scripts/make-icon.swift`.

### Самопроверка

```bash
Scripts/selftest.sh
```

57 проверок: форматы без потерь возвращают звук бит в бит, положение во времени
и порядок каналов не меняются, высота тона и громкость сохраняются, заявленная
разрядность соответствует запрошенной. Судьями выступают ffmpeg и python3 —
чтобы проверка не сводилась к «наш код подтверждает наш код». Нужны оба.

Запускать после любой правки движка.

### Задержка декодера MP3

MP3 несёт задержку кодировщика и декодера. Величина первой пишется в служебный
заголовок Xing/LAME, вторая постоянна по стандарту — 529 сэмплов.

- **Файл с заголовком:** система вычитает всё, результат совпадает с оригиналом
  сэмпл в сэмпл.
- **Файл без заголовка:** задержку кодировщика узнать неоткуда. CoreAudio
  вычитает известные 529, ffmpeg не вычитает ничего — поэтому наш результат
  оказывается на 529 сэмплов (11 мс) ближе к правде, чем у конвертеров на
  ffmpeg. Полностью совпасть не может ни один декодер.

Практическое следствие: **не смешивайте в одном проекте дорожки из разных
конвертеров** — они разъедутся на 11 мс, и при наложении получится гребенчатая
фильтрация, слышимая как изменение тембра. Перегоняйте весь материал одним
инструментом. Поведение закреплено проверкой в `selftest.sh`.

### Подпись

Приложение и оба фреймворка обязаны быть подписаны **одной командой**. Включён
hardened runtime, а он требует проверки подлинности библиотек: при подписи
ad-hoc (`CODE_SIGN_IDENTITY = "-"`) Team ID отсутствует у всех участников, и
загрузчик отвергает встроенный фреймворк с ошибкой «different Team IDs» —
приложение падает при запуске, ещё до первой строки кода. Поэтому в проекте
задан `DEVELOPMENT_TEAM = 388FG4KTF8`; менять на ad-hoc нельзя.

## Лицензии

- **LAME 3.100** — LGPL-2.1. Линкуется **динамически**, отдельным фреймворком:
  это выполняет требование LGPL о возможности подменить библиотеку. Текст
  лицензии — `Vendor/LAME-LICENSE-LGPL-2.1.txt`.
- **libogg / libvorbis** — лицензия BSD, ограничений нет.
  Текст — `Vendor/VORBIS-LICENSE-BSD.txt`.

Обе лицензии нужно указать в разделе «О программе».

## Обновления

Автообновление — через [Sparkle](https://sparkle-project.org), фид читается из
`appcast.xml` в этом репозитории
(`https://raw.githubusercontent.com/white-currant/Agave/main/appcast.xml`).
Меню «Проверить обновления…» доступно, когда собрано с флагом `SPARKLE_ENABLED`
(включён в обеих конфигурациях — Debug и Release).

Разовая подготовка на машине разработчика:

1. Сертификат **Developer ID Application** в Xcode (Settings → Accounts →
   Manage Certificates → "+"). Team ID `388FG4KTF8`.
2. Профиль нотаризации:
   ```bash
   xcrun notarytool store-credentials "yuliontool" \
     --apple-id <apple-id> --team-id 388FG4KTF8 --password <app-specific-password>
   ```

Релиз новой версии:

```bash
# поднять MARKETING_VERSION/CURRENT_PROJECT_VERSION в pbxproj, затем:
Scripts/release.sh
```

Скрипт архивирует, экспортирует под Developer ID, нотаризует, степлит тикет,
подписывает zip EdDSA-ключом Sparkle (`Scripts/sparkle-bin/sign_update`,
ключ — отдельный на аккаунт `agave` в Keychain) и дополнительно собирает DMG
(`create-dmg`, `brew install create-dmg`) — отдельно нотаризованный и
застеплённый, с обычным окном «перетащи в Programs». Печатает готовый `<item>`
для `appcast.xml`. Два файла с разным назначением:

- **zip** — то, что качает и ставит сам Sparkle при автообновлении;
- **dmg** — то, что скачивает человек с страницы релиза при первом знакомстве.

Дальше руками: `gh release create` с обоими файлами и вставка `<item>`
в `appcast.xml` с пушем (в `<item>` попадает только zip — DMG в фид Sparkle
не участвует).

Приватный EdDSA-ключ живёт только в Keychain этой машины — при переезде на
другую машину его нужно экспортировать (`Scripts/sparkle-bin/generate_keys -x`,
берётся из полного архива Sparkle) и импортировать там же.
